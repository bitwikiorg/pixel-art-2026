Open research laboratory · representation · computation · memory

One pixel. Many possible universes.

Pixel Photon Lab studies a precise question: what happens when a pixel is treated as a general-purpose information carrier and computational address rather than being defined in advance as only a color value? The object at an address may be a bit, vector, tensor, memory, token set, neural process or nested field—but every real implementation has finite bits, parameters and compute.

The invariant

Address + carrier + interpretation.

A visible pixel is an address. The carrier state at that address is finite. An interpreter determines what that state means and how it participates in a larger system.

The laboratory changes one layer at a time so we can tell whether an effect comes from encoding, representation, topology, computation, memory or learning.

pixel = address + carrier state + interpretation

bit → vector → tensor → hypervector → token set → memory → subfield

Evidence labels

Every experiment says what kind of evidence it is.

Mechanics demos are useful, but they are not trained results. Learned models are useful, but task accuracy is not automatically evidence for MPF. Exact codecs and GPU operators have different correctness criteria again.

EXACT

Codec / deterministic identity

Round-trip or CPU↔GPU correctness can be asserted exactly.

LEARNED

Train / test protocol

Held-out metrics, seeds, baselines and resource counts are required.

MECHANICS

Visualization only

Shows how an operator behaves; never presented as evidence of usefulness.
