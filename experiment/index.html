Change what a pixel means.

The primitive in this laboratory is not a color and not one fixed neural architecture. A pixel is a spatial address whose internal interpretation can change: scalar, vector, tensor, neural unit, micro-transformer, memory object, subfield, or something recursively larger.

Core scope: a pixel can be interpreted as a scalar, vector, tensor, neural unit, micro-transformer, memory object, subfield, or something recursively larger. The lab compares those interpretations rather than prematurely defining MPF as one recurrent-grid architecture.

The “infinite universe” language is an architectural metaphor, not a storage claim. A finite machine always has finite memory. The open-ended part is the interpretation: there is no requirement that one visible pixel correspond to one scalar. Human-readable visualization is always a finite projection of a richer computational state.

Carrier analogy

A visible pixel can carry more than illumination.

A useful analogy is a photon: perceived brightness is not its complete physical description; frequency, phase, polarization, momentum and helicity can also matter. The analogy is not literal physics. It reminds us not to confuse the human-visible projection with the complete state of the carrier.

Likewise, an MPF pixel can have a visible color while its computational object is a vector, tensor, token set, memory system, neural unit, or nested field.

visible pixel = projection(state)

Experimental program

From pixel primitive to systems.

The project should compare interpretations at equal resource budgets, then compose the useful ones into larger architectures. Not every experiment needs to be a recurrent grid.

NEXT TRAINED MODEL

Tensor-pixel network

Give each pixel a structured latent tensor and compare it with an equal-scalar-count flat vector. Ask whether internal axes or factorizations help.

NEXT TRAINED MODEL

Transformer-pixel field

Give every pixel several internal tokens and a shared micro-transformer, then compare attention inside pixels with attention between pixels.

COMPARISON

Field Transformer

Treat each pixel as a token and perform attention across addresses. This is the opposite factorization from a micro-transformer inside every pixel.

RECURSION

Field inside field

A pixel contains a subfield; regions contain subregions; shared rules may operate across scales. This is the experiment that can make “recursive” concrete.

MEMORY

Persistent semantic object

Write information, remove the input, save/restore state, query it later, damage it, and measure what persists or regenerates.

COMPRESSION

Quantized pixel universe

Replace float state with learned codes, sparse state or product VQ and measure utility per stored bit across pixel interpretations.

TOPOLOGY

Learned semantic geography

Compare fixed 2D address, learned placement, graph neighborhoods and self-organizing layouts. Ask whether where information lives becomes useful.

GEOMETRY

Hyperdimensional / hyperbolic state

Separate dimensionality from geometry. Test very high-dimensional compositional state and hyperbolic metrics where hierarchy predicts an advantage.

ALBUM

Fields of fields

Let persistent fields retrieve, communicate with and consolidate into other fields. The unit of computation can become a whole field, not only a pixel.

Resource discipline: browser experiments stay small and inspectable. Trained tensor/transformer variants belong in the repository reference experiments when they exceed safe browser compute. Comparisons should report parameter count, scalar state, approximate compute, stored bits where relevant, and task performance.
